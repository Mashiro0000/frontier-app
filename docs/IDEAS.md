# Ideas (v0.1)

> Parking lot. Unvetted ideas live here so they do not clutter the roadmap. Nothing here is planned.

- Pick the best model for a message by itself (Stage 6 only shortlists models for a task the person names, and has no scores, D-023)
- Compare two models' answers side by side
- Support local models (for example through Ollama)
- Keyboard-first command palette
- Export a conversation to Markdown
- Syntax colours in code blocks (a package, or a small tokenizer of our own for a few languages; D-025)
- The parts of Markdown the reader leaves out: task lists, footnotes, setext headings, reference links, entities (D-025)
- A deny-by-default permission handler for the window, so the page can ask for nothing it does not use (it uses the clipboard write); Electron grants every request when none is set (D-025)
- Keep the old reply when one is regenerated, and the later messages when one is edited (versions of a reply or of a chat; D-026 replaces them)
- Ask before Regenerate replaces a reply (D-026 does not)
- Default instructions for every new chat (a setting), or instructions per model (D-027 keeps one text per chat, and a new chat starts without)
- Ask before Escape throws away a long unsaved draft in the Instructions box (D-027 does not), and a mark on a chat that came from outside the app
- Automated tests for `useChat` (needs a test runner; none is set up, see D-007)
- Show what a reply cost on a chat opened from History (8.1 shows it live only: it is not saved with the message, so a chat file stays version 3; saving it would be version 4, and one more step a build cannot take back, D-030)
- Stop a reply in the middle when its running cost would pass a limit (8.2 only checks before a request, so one reply can end over; D-031)
- A warning in the empty chat or the chat bar when a limit is nearly used (say 80%), and a limit that resets on a day the person chooses (billing day) instead of the 1st (D-031)
- "Don't ask again in this chat" on the question before a large request: in a long chat on a dear model every message after the first asks, because the whole conversation goes out again (D-032 asks every time, and says why)
- Show in the large-request question how much of today's and this month's limit would be left if the reply ran to its ceiling (D-032 shows the request's own most; the limits' sums are in Settings > Usage)
- Work out whether the provider's cache is probably still warm (the last reply in this chat ended under five minutes ago) and say so in the question, since a cached conversation costs far less than the "up to" figure (D-032 can only say it may be)
- (Done in 10.1, D-039: raising a limit, "No limit", a higher amount to ask above and "Never ask" now need the person's yes in the system's own message box.) Left: the question before a large request itself is still answered in the page (`chat.confirm`, D-032), so a hostile page can send up to the limits; a system box for that question too, if the limits are not enough (D-039)
- Keep the app's data folder (the ledger, `limits.json`, `ask-first.json`, and since Stage 9 the `attachments/` folder) outside every folder a tool may read or write, and outside what Stage 10's memory or Stage 12's folder choice can name, before Stages 12 and 13 (D-033)
- Measure the input guess (bytes divided by 3) against a real tokenizer for text that tokenizes badly: long random strings, minified code, runs of digits (D-030, D-033)
- Compact the usage ledger (it only grows: two lines a request; older months could be rolled into one line each), and export it as a CSV (D-030)
- The pricing modifiers the ledger does not apply: Fast mode, the Batch API, data residency (1.1x), web search, and discounts or tax on an invoice (D-030)
- Server-side refusal fallbacks for the provider, once there is a real key to try them with (D-012)
- Use Chromium's network stack (`net.fetch`) for the provider calls, so a system proxy is honoured
- Trim or summarise old turns when a conversation gets long (D-013)
- Check `registry/models.json` before every build with the same validator the app uses (`src/shared/registry.ts`),
  so a typo cannot ship (D-014)
- Update the registry without a new release: a checked copy in the data folder, written in place (D-010, D-014)
- Remember an effort level per chat instead of per model, or let a message ask for one (D-024 keeps one level per model)
- Show what the thinking of a high effort level cost on its own (8.1 counts it, in the output, but no provider reports it apart; D-024, D-030)
- When a model answers "not found" (a retired model, as Haiku 4.5 will be; it was removed from the registry first, D-036), offer to switch to another
- A documented model for "Quick answer" (its only row was Haiku 4.5's; it now says "No suggestion", D-036)
- Show the retirement date of a model in Settings (needs a field in the registry)
- Rename a saved conversation (the title is the first message; editing the file by hand already works)
- Search saved conversations, and group them by day
- A sidebar for History instead of a dialog (wide windows), keeping the dialog for narrow ones
- Export or copy a saved conversation as Markdown (the idea above, now with something to export from)
- "Delete all", and an option to clear conversations older than some age
- Encrypt saved conversations with the operating system's secure storage (D-016 says what it would cost)
- Run `tools/regress.mjs` automatically (a pre-release script or CI); today it is run by hand, about 55 minutes
- Gemini as the third provider (an adapter and a registry entry; the provider tables will not compile without them, D-018)
- Windows Credential Manager instead of safeStorage files for the keys (needs a native keyring package; D-020)
- Chat Completions as a fallback for OpenAI if the Responses API misbehaves (D-022)
- Image input and tools: the registry already records which models take them (D-019)
- Run `tools/regress.mjs` automatically before a release; today it is run by hand
- A progress line while a restore runs ("Adding 412 of 1000..."): 1000 chats took 109 s in this PC's EFS-encrypted data folder and the page shows only "buttons off" (D-034); and a restore that writes several chats at once, if the copy-then-delete rule allows it
- A mark on a chat that came from a backup (or from any file brought in), and a look at its messages in the preview, not only the titles: a made-up chat is read by the model as history (D-034; the same gap as D-027's)
- Back up the settings, the usage ledger and the limits with the chats (D-034 backs up chats only), and a "restore everything" that asks about each part
- A readable Markdown export of one chat or all of them, next to the JSON backup that restore reads (the owner chose JSON only for 8b.1)
- Encrypt the backup file itself with a password the owner types, for a backup that is kept in a synced folder (D-034 says a backup is plain text, and 8b.3 does not cover it, D-035)
- A password-based key as a second way to encrypt the chats, for chats that must open on another computer or account: the secure storage ties them to this Windows account, so a copy elsewhere (and a reset profile) cannot open them (D-035)
- A progress line while encryption is turned on or off, like the one for a restore above: it rewrites every chat one at a time (a few seconds for dozens; about two minutes for 1000 in this PC's EFS data folder), and the page shows only "buttons off" (D-035)
- A way to tell the person which chats are still plain when a conversion was cut short (D-035 shows a count and "Encrypt the rest"; a list of titles would help)
- Wiping the old plain bytes after encrypting: turning encryption on rewrites each file in place, but a solid-state disk, EFS, a shadow copy or a file-system journal may keep the plain text it replaced, and there is no reliable wipe from inside an app (D-035 says so; a note in Settings, or advice to turn on full-disk encryption)
- Tell the person at start, before they type, when encryption is on and the key cannot be used (the Settings section and the History dialog say so today, and the "Not saved" badge appears after the first message; a notice in the chat bar would come sooner) (D-035)
- A shorter keyboard path through a long History list: three Tab stops per row now (open, Export, Delete), and a person with 150 chats tabs 450 times to get past the list (D-034; where Shift+Tab goes from the first row was not measured)
- Decode attached pictures in a sandboxed utility process instead of the main process: Electron's `nativeImage` (used to make a picture smaller, turn a photo upright and draw the chip's small picture) runs in main, outside the renderer's sandbox, on bytes from the person's files, pastes, drops and restored backups. The header checks of 9.1 stand before it (D-038)
- Remove a PDF's metadata before it is sent (the author, the program, dates): it needs a PDF library, a new dependency, so 9.1 sends a PDF as it is and says so on its chip (the owner's answer 2, D-037)
- Stop sending one file of a chat without starting a new chat: every file of a chat goes with every message (D-028), so a big PDF costs again each time; today the way out is a new chat (D-037)
- Show how many tokens each attached file is guessed at on its chip, so the cost of keeping it in the chat is seen before sending (9.4 shows it only in the question before a large request)
- A provider's voice for "Read aloud", behind the same button, once OpenAI (or another provider) has a text-to-speech endpoint that is not shut down: every OpenAI TTS model (`tts-1`, `tts-1-hd`, `gpt-4o-mini-tts`) ends on 6 January 2027 and the named replacement is a Realtime model (D-047). Today a reply is read with the voices of this PC
- "Read every reply" as a switch (the plan's G): today a reply is read only after a click on its own button, so that nothing is ever spoken by surprise. It would be a third switch in Settings > Voice that asks like the others
- Keeping recordings or transcripts, only when the person switches it on and says where (the roadmap's "unless the owner switches it on" was not built, D-047: nothing is stored, which is the safer way round)
- Voice to voice (the Realtime API: a live two-way connection with audio in and out): a different kind of feature from push-to-talk and read-aloud, with its own cost and its own safety questions (D-047 lists what it would need)
- A language choice for "Speak to type" (today the model decides what it hears; no `language` or `prompt` field is sent, on purpose) and a way to send the person's voice-typed words straight away, if the owner ever wants it (today the words go into the message box and the person presses Send)
- Show the reading position while a reply is read aloud (the sentence that is being said), and a speed or voice that is remembered per language, if the system's voices differ much (D-047 keeps one voice and one speed)
- Name the later kept files (workspace, connectors, voice settings, the undo journal) in the sentence that Settings > Saved chats shows after encryption is turned on or off: it still lists only the instructions, notes, projects, tool settings and the audit log (D-039, D-041), although the others are rewritten with the chats too
